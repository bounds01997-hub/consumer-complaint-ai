# 架构说明

## 当前状态

本仓库为 Python 研究骨架。核心包目前只有说明性的 `__init__.py`；以下为拟议职责与数据流，尚未实现接口、规则加载器、模型调用或界面。

## 模块职责

| 目录 | 拟议职责 | 边界 |
| --- | --- | --- |
| `src/preprocessing` | 文本规范化、脱敏辅助、去重与输入整理 | 脱敏结果也不得自动视作可公开数据 |
| `src/classification` | 已确认任务的分类候选结果 | A/B/C 定义由用户确认，不自动创造标签 |
| `src/semantic_analysis` | 按授权维度生成多维语义候选分析 | 不认定事实、责任或因果关系 |
| `src/validation` | 检查输出格式、标签有效性和明确的规则约束 | 不核验业务事实或外部证据 |
| `src/review` | 整理待复核项、人工修订与追溯记录 | 不自动作出业务处置决定 |
| `experiments` | 三种方法的独立对照入口 | 不在每个实验中复制核心处理逻辑 |
| `app` | 后续本地 Streamlit 展示与审核入口 | 当前无可运行页面，不上传真实数据 |
| `scripts` | 后续本地辅助任务 | 默认不得上传数据或记录密钥 |

## 拟议数据流

```text
本地授权数据 → 预处理 → 分类 / 多维语义分析 → 输出校验 → 人工复核
                               ↑
                  本地授权业务标准与标签映射
```

分类与语义分析是否串行或并行，待任务定义后确定。校验不通过或无法确定标签时进入人工复核。代码仅使用经明确授权和版本化的标准；缺少标准时不得自动补全业务标签。

## 公开模板与本地业务内容

`rules/label_schema.yaml` 是可解析的 YAML 结构模板，并非已实现的 JSON Schema 校验器。它只保留六个位置，名称为空、标签集合为空；六层含义与相互关系均待用户本地定义。

`rules/classification_rules.yaml` 只描述规则条目字段，`rules` 为空，不提供可执行规则。模板中的 `null` 表示尚未填写，不是通配符、默认标签或有效业务取值。两个文件均标为 `template_only`，不得直接用于真实分类。

原始文件建议放在受控的仓库外位置；如需本地副本，可使用被忽略的 `data/`。实际标签和规则副本放在 `rules/local/`，不得向公开模板回填。模板版本与业务标准版本分别记录。

`rules/` 默认只放行上述三个公开文件，新增公共模板时需有意更新 `.gitignore` 并审查内容；其他本地文件默认被忽略。此策略不能阻止把敏感内容误填入已公开的模板，提交前仍须逐项检查。

## 配置和依赖

公开仓库只包含 `.env.example`；本地 `.env` 存放配置。路径和变量名是未来实现约定，没有配置读取行为。首批依赖仅为 PyYAML 和 python-dotenv；模型、SDK、界面和测试依赖按实际实现需要添加。

业务接口和数据字段在标准确认后定义，避免提前固定未经确认的标签结构。第一阶段不引入 RAG、Agent、模型微调或业务证据核验模块。
